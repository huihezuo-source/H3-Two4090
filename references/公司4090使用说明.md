# 公司两台 4090 的使用说明（给同事）

公司有两台装好 MiniMax H3 的机器，同一个办公室网络里的任何电脑都可以把视频任务发过去跑，不用自己装模型。

| 机器 | 局域网地址 | ComfyUI 地址 | 模型位置 |
|---|---|---|---|
| WJ | 192.168.0.186 | http://192.168.0.186:8188 | D:\ComfyUI\models |
| XW | 192.168.0.246 | http://192.168.0.246:8188 | C:\ComfyUI\models |

XW 是 ComfyUI 0.45.2，装了 MiniMax-H3-Image，能出首帧（400 万像素一张约 1 分钟）；WJ 还是 0.44.0，模型文件已下好，升级后同样能出首帧。两台都没有配音模型，对白由 H3 直接按声音描述生成。

两台都是 RTX 4090 24GB、32GB 内存、页面文件 64GB。模型是 H3 ref2va pruned_int8 主模型 + nvfp4 文本编码器（+ turbo 4 步 LoRA、H3 Image 主模型和 VAE），5 秒 640×384 20 步约 2 分钟，10 秒 448×608 约 4 到 5 分钟；4 步加速 14.5 秒 448×608 约 3 分钟（含冷加载）。

## 管理员要先做一次（机器主人做）

两台机器 2026-11-12 起已经开放给办公室网络：启动脚本里是 `--listen 0.0.0.0`，防火墙里已有放行 Python 的入站规则，两台互相用局域网地址都能打开。重装或换机器时再做下面两件事：

1. 编辑启动脚本（WJ 是 `D:\ComfyUI\start_h3.bat`，XW 是 `C:\ComfyUI\start_h3.bat`），把 `--listen 127.0.0.1` 改成 `--listen 0.0.0.0`，保存后关掉正在跑的 ComfyUI 窗口重新双击启动。
2. 如果别的电脑打不开 8188，放行防火墙端口：右键开始菜单 → 终端（管理员），粘贴下面一行回车：

```
netsh advfirewall firewall add rule name="ComfyUI 8188" dir=in action=allow protocol=TCP localport=8188 profile=any
```

机器重启后 ComfyUI 不会自动起，要双击一次启动脚本；想开机自启，把一个内容为 `start "" /min "D:\ComfyUI\start_h3.bat"` 的 `start_h3.bat` 放进 `Win + R` → `shell:startup` 打开的文件夹（XW 把 D: 改成 C:）。WJ 已加，XW 还没加。

## 升级 ComfyUI 到 0.45.2（出首帧必须）

0.44 自带的 H3 Image 节点是预发布版，加载正式模型会报 size mismatch。升级脚本 `scripts/upgrade_comfyui_045.py`：拷到机器上，在 PowerShell 里用 ComfyUI 的 venv python 运行（`C:\ComfyUI\.venv\Scripts\python.exe upgrade_comfyui_045.py`），它会下载 0.45.2 压缩包、停掉 ComfyUI、把旧核心文件备份到 `C:\h3\backup044`、覆盖、装依赖、重新启动，约 10 分钟。依赖走清华镜像；阿里云镜像在这两台机器上大包会无声卡死。脚本顶部的 ROOT、H3 两个路径按机器改（WJ 是 D: 盘）。

## 同事怎么用

### 方式一：直接在浏览器里用 ComfyUI

打开 http://192.168.0.186:8188 或 http://192.168.0.246:8188，左侧「工作流 → 模板」里搜 MiniMax H3，像本机一样拖图、写提示词、点运行。生成的视频在页面右侧的队列里能预览和下载。

### 方式二：用这套脚本（Claude Code 技能）

1. 装好本仓库（见根目录 README 的「安装」）。
2. 告诉脚本用哪台机器：

```bash
export COMFY_URL=http://192.168.0.186:8188
python3 scripts/h3_ref2va.py examples/h3_job.json --wait out/video
```

3. 一条视频分成几段同时跑两台：把 `scripts/farm_machines_company.json` 复制为 `scripts/farm_machines.json`，然后

```bash
python3 scripts/farm.py jobs.json out/farm
```

谁空闲谁接下一段，一台失败会自动换另一台重试。

4. 想看进度：`python3 scripts/dashboard.py` 后打开 http://localhost:8765 ，机器列表在 `scripts/dashboard_machines.json`，把地址改成上面两台的即可。

## 一起用的规矩

- 两台机器都是一个队列，先提交先跑。提交前在浏览器里看一眼队列，别在别人跑长片段时一口气塞十几条。
- 一次提交别超过 15 秒、分辨率别超过 1280×720，内存会见底，整台机器都会卡住。长视频按镜头拆成段再用 farm.py。
- 不要改机器上 `models` 目录里的文件，也不要在上面装新节点；要加模型先在群里说一声。
- 出片保存在机器的 `ComfyUI\output` 下，会定期清理，拿到结果请及时下载到自己电脑。

## 出问题怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器打不开 8188 | ComfyUI 没起，或防火墙没放行 | 去机器上双击启动脚本；检查上面的两步 |
| 提交后一直排队不动 | 前面有人的任务在跑 | 看队列，等；或者换另一台 |
| 报内存不足或整台机器卡死 | 片段太长或分辨率太高 | 缩短到 10 秒以内、降分辨率；机器主人把页面文件保持在 64GB 以上 |
| 第一条特别慢（5 到 8 分钟） | 冷加载 45GB 模型 | 正常，第二条起约 2 分钟 |
| 出来的人物对着旁白对口型 | 旁白写进了提示词 | 旁白段的提示词里不要写台词，见 SKILL.md |

## 不在办公室时：用 RustDesk 的 TCP 隧道

在办公室 WiFi 里直接用上面的局域网地址，不需要 RustDesk。在家或出差时，两台机器都开着 RustDesk，用它的「TCP 隧道」把你电脑的一个端口转到机器上的 8188，之后所有脚本和浏览器都当成本机在用。机器的 RustDesk ID 和密码找机器主人要，不写在这里。

1. 装 RustDesk 客户端（rustdesk.com，Mac 和 Windows 都有），打开后在左侧「ID」框输入机器的 ID，点「连接」，输入密码连上一次，设备会出现在右侧的「最近会话」里。
2. 在那台设备的卡片上点右上角的 ⋮ → 「TCP 隧道」（英文版叫 TCP Tunneling）。
3. 填三项：本地端口 `18188`，远程主机 `127.0.0.1`，远程端口 `8188`，点「开始」。这个隧道窗口要一直开着，关了就断。
4. 第二台机器同样做一遍，本地端口改成 `18189`。
5. 浏览器打开 http://127.0.0.1:18188 就是 WJ 的 ComfyUI，http://127.0.0.1:18189 就是 XW。用脚本时 `export COMFY_URL=http://127.0.0.1:18188`；双机并行用仓库自带的 `scripts/farm_machines.json`（已经写好这两个端口，不用改），工作台用 `scripts/dashboard_machines.json`。

连不上时：确认机器上 ComfyUI 在跑（远程桌面看一眼黑窗口）；RustDesk 隧道走的是机器自己的 127.0.0.1，不受防火墙影响；隧道只在你的电脑上有效，别人要用得各自建一条。机器主人远程维护机器（重启 ComfyUI、改脚本）也是先连 RustDesk，再用远程桌面操作。
